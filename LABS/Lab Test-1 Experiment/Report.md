# Simple CMS Blog - Lab Report

## 1. Title

**Simple CMS Blog - Content Management System**

## 2. Objective

To design and develop a simple Blog Content Management System using Node.js, Express.js, EJS and MongoDB.

The system allows users to create blog posts, view all posts and view an individual blog post.

## 3. Technologies Used

- Node.js
- Express.js
- EJS
- MongoDB
- MongoDB Node.js Driver
- HTML
- CSS

## 4. Introduction

A Content Management System (CMS) is a system that allows users to create and manage content.

In this project, a simple blog CMS has been developed. Users can create blog posts by entering a title, content and author name. The posts are stored in MongoDB and can be viewed through web pages rendered using EJS.

## 5. Database Details

The application uses MongoDB for data persistence.

### MongoDB Connection

```text
mongodb://127.0.0.1:27017
```

### Database

```text
cms_lab
```

### Collection

```text
posts
```

### Post Fields

Each post contains:

- `title`
- `content`
- `author`
- `createdAt`

The `createdAt` field is automatically generated by the backend.

## 6. System Features

### 6.1 Create New Post

The user can create a new blog post by entering:

- Title
- Content
- Author

The form sends the data to the backend using a POST request.

### 6.2 Display All Posts

The home page retrieves all posts from MongoDB and displays:

- Post title
- Author
- Creation date and time

The post title is clickable.

### 6.3 View Individual Post

When the user clicks a post title, the application retrieves the selected post from MongoDB using its unique `_id`.

The complete post is then displayed on a separate page.

### 6.4 Automatic Date and Time

The creation date and time are generated automatically by the backend using:

```javascript
new Date()
```

The user does not enter the creation date manually.

### 6.5 Validation

The application checks that:

- Title is not empty.
- Content is not empty.
- Author is not empty.

If any required field is empty, the post is not inserted into MongoDB.

## 7. Application Routes

| Method | Route | Purpose |
|---|---|---|
| GET | `/` | Display all posts |
| GET | `/posts/new` | Display create-post form |
| POST | `/posts` | Create a new post |
| GET | `/posts/:id` | Display an individual post |

## 9. Working of the Application

### Step 1: Start MongoDB

The local MongoDB server is started and runs on:

```text
mongodb://127.0.0.1:27017
```

### Step 2: Start the Node.js Server

The application is started using:

```bash
node app.js
```

The Express server runs on:

```text
http://localhost:3000
```

### Step 3: Open the Home Page

The user opens:

```text
http://localhost:3000
```

The application retrieves the posts from MongoDB and displays them.

### Step 4: Create a Post

The user clicks **Create New Post**.

The user enters:

- Title
- Content
- Author

After submitting the form, the backend validates the fields and stores the post in MongoDB.

### Step 5: View All Posts

After successful insertion, the user is redirected to the home page.

The newly created post is displayed in the list.

### Step 6: View Individual Post

The user clicks the title of a post.

The application uses the MongoDB `_id` to retrieve that specific post and displays its complete content.

### 13.5 Confusion Between `post` and `posts`

There was confusion between the names `post` and `posts`.

The final naming was:

```text
posts
```

for multiple posts and the MongoDB collection.

```text
post
```

for a single individual post.

For example:

```text
posts.ejs
```

displays multiple posts, while:

```text
post.ejs
```

displays one post.

### 13.11 Unnecessary Files and Folders

The following files and folders were intentionally excluded:

```text
node_modules/
.vscode/
.env
```

#### `node_modules/`

This folder contains installed Node.js dependencies.

It does not need to be uploaded because dependencies can be installed again using:

```bash
npm install
```

#### `.vscode/`

This folder can contain personal VS Code settings and configuration files.

It was therefore excluded from the repository.

#### `.env`

This file can contain environment variables and sensitive configuration information.

It was excluded using `.gitignore`.
