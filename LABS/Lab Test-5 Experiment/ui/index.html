Same task, different syntax

Switch between SQL and MongoDB Query Language to compare the operations.

-- Students in CSE
SELECT * FROM students WHERE branch = 'CSE';

-- Enrolled after January 2024
SELECT * FROM students
WHERE enrollment_date > '2024-01-31';

-- Update branch
UPDATE students SET branch = 'AI/ML'
WHERE email = 'bilal@example.com';

-- Delete
DELETE FROM students
WHERE email = 'divya@example.com';
// Students in CSE
db.students.find({ branch: "CSE" })

// Enrolled after January 2024
db.students.find({ enrollment_date: {
  $gt: new Date("2024-01-31")
}})

// Update branch
db.students.updateOne(
  { email: "bilal@example.com" },
  { $set: { branch: "AI/ML" } }
)

// Delete
db.students.deleteOne({ email: "carla@example.com" })

COMPARISON

Two approaches to persistence

PostgreSQL

Structure first

Typed columns, constraints, SQL, joins and strong transactional behavior make it ideal for predictable core student data.

  • Explicit schema
  • Native relationships
  • SQL querying
  • JSONB when flexibility is needed
MongoDB

Document first

JSON-like BSON documents make evolving or nested records convenient when the shape of each record can vary.

  • Flexible document shape
  • Nested data is natural
  • Document-shaped queries
  • Secondary indexes and aggregation

HYBRID APPROACH

PostgreSQL + JSONB

Keep strict columns such as ID, name and email, while storing optional skills, clubs or metadata in an indexable JSONB profile.

{ "skills": ["python", "sql"], "clubs": { "robotics": true } }
